# HANG reference-player certification

This is an integration harness, not an application or a codec implementation.
It publishes synthetic media through the plugin, then measures decoded output
from the real moq.dev player. Run only against a test namespace. No credentials
are embedded, persisted, or needed for the local/public anonymous cases.

## Pinned reference

- MOQX: 0.9.0, from this project's lockfile.
- moq-dev/moq: `fd477082c43c3c0738fb62d077d85ea078f10045` for relay and JS player.
- Player: `@moq/watch` 0.5.2 at that commit, with its frozen Bun lockfile.
- Relay: `moq-relay --server-version moq-lite-05` built with `cargo build --locked`.

## Prepare the reference player

In a separate temporary checkout of the exact reference commit, run
`bun install --frozen-lockfile`. Copy `browser/index.html` and `browser/main.ts`
to `<reference>/interop/`, and `browser/interop.vite.ts` to the reference root.
Run `bun x vite --config interop.vite.ts` there. The server binds only loopback,
port 5179, and enables cross-origin isolation for the audio worklet.

Install Playwright in a separate temporary directory (`npm install playwright`)
and copy `browser/check.mjs` there. Set `CHROME_EXECUTABLE` to a Chrome binary,
or install Playwright's Chromium. The test uses an isolated browser profile;
the autoplay flag is scoped to that browser. It does not disable TLS validation.

## Synthetic media

Create a fresh directory and set `MOQX_INTEROP_MEDIA` to its absolute path.
Generate two four-second files (FFmpeg with libx264/libopus required):

```sh
ffmpeg -f lavfi -i testsrc2=size=160x90:rate=10 -t 4 -c:v libx264 \
  -profile:v baseline -pix_fmt yuv420p -bf 0 -g 10 "$MOQX_INTEROP_MEDIA/video.mp4"
ffmpeg -f lavfi -i sine=frequency=440:sample_rate=48000 -t 4 -c:a libopus \
  -ac 2 "$MOQX_INTEROP_MEDIA/audio.ogg"
```

## Local relay and endpoints

Use a short-lived (10-day) P-256 ECDSA certificate generated by OpenSSL 3 for
localhost and 127.0.0.1. Supply its PEM certificate/key to the pinned relay.
Expose its UDP port only on loopback. Native QUIC and browser WebTransport use
the same relay listener. Set:

```sh
export MOQX_LITE_ENDPOINT=moql://127.0.0.1:24464/
export MOQX_BROWSER_RELAY=https://127.0.0.1:24464/
export MOQX_LITE_CA_FILE=/absolute/test-cert.pem
export MOQX_INTEROP_BROADCAST=membrane-proof/unique-run.hang
```

Set `MOQX_CERT_HASH` to the SHA-256 fingerprint of the **certificate DER**,
without colons. Only the browser uses this pin. Do not pass a private key to
the browser. For a publicly trusted relay, omit `MOQX_CERT_HASH` and use the
system CA bundle for the native client. Never disable peer verification.

## Run

From this plugin checkout:

```sh
MIX_ENV=test mise exec -- mix run scripts/interop/publish_legacy.exs
```

After publication readiness, run `node check.mjs` from the temporary Playwright
directory with the same broadcast and browser relay environment. The publisher
waits for both media subscribers, then paces twenty seconds of synthetic media.
It keeps the publication alive for thirty more seconds for receiver inspection,
then terminates. Pacing is a media clock, never a delivery acknowledgement.

The browser test passes only after at least twenty decoded video frames,
video/audio playback timestamps beyond one second, and a non-zero audio
analyser signal. It records the exact browser version and observed samples.
Transport bytes, a catalog, or AudioContext time alone do not satisfy this test.

## CMAF mode

Set `MOQX_INTEROP_CONTAINER=cmaf` to select the explicit `Hang.CMAF` adapter.
Generate fragmented fixtures in the same media directory:

```sh
ffmpeg -i "$MOQX_INTEROP_MEDIA/video.mp4" -c copy \
  -movflags +frag_keyframe+empty_moov+default_base_moof "$MOQX_INTEROP_MEDIA/video-cmaf.mp4"
ffmpeg -f lavfi -i sine=frequency=440:sample_rate=48000 -t 4 -c:a aac -ac 2 \
  -movflags +frag_keyframe+empty_moov+default_base_moof -frag_duration 1000000 \
  "$MOQX_INTEROP_MEDIA/audio-cmaf.mp4"
```

This mode sends complete `moof`/`mdat` pairs and preserves internal decode
times. Unlike legacy mode, fragments are sent once: changing transport PTS
cannot retime a repeated MP4 fragment. The fixture splitter handles the
32-bit boxes produced by these commands, not arbitrary MP4 inputs.

## Reverse direction: pinned reference publisher → plugin → decoder

Run the pinned `moq` CLI's `import fmp4` with a live FFmpeg fragmented-MP4 input.
For example (add `--client-tls-root` for a local CA-signed relay):

```sh
ffmpeg -re -f lavfi -i testsrc2=size=160x90:rate=10 \
  -f lavfi -i sine=frequency=440:sample_rate=48000 -t 40 \
  -c:v libx264 -profile:v baseline -pix_fmt yuv420p -bf 0 -g 10 \
  -c:a aac -ac 2 -movflags +frag_keyframe+empty_moov+default_base_moof -f mp4 - | \
  moq --client-connect "$MOQX_LITE_ENDPOINT" --client-version moq-lite-05 \
    --broadcast "$MOQX_INTEROP_BROADCAST" import fmp4
```

Set `MOQX_INTEROP_OUTPUT` to a fresh, existing temporary directory. While the
reference publisher is live, run:

```sh
MIX_ENV=test mise exec -- mix run scripts/interop/receive_cmaf.exs
```

The receiver discovers and selects both catalog offers, receives three chunks
per track through `CatalogSource`/`Source` and `Hang.CMAF`/`FromTrack`, checks
advancing PTS, and writes initialization plus untouched fragment payloads.
FFmpeg then independently decodes those received files. Success requires at
least twenty decoded video frames and at least 96,000 non-silent audio samples.
This is capture-then-decode verification, not a real-time decoder embedded in
core Source/Sink. Keep the codecs/muxers/decoders outside the transport elements.

The harness does not substitute for the full lifecycle tests.
Clean up only task-created processes/directories after
they have finished; never remove or rotate supplied credentials.
